How mitigations work

When diysca can't reach a system (another network, an air gap, a team that owns the deployment), approve its findings instead of patching them yourself. The approval becomes a mitigation: the findings, a playbook pinned to the versions your repos offer, and links to report back.

  1. Approve findings on the Findings page or a finding's page (people with the login; agents only if agents_can_approve is on).
  2. Hand off: agents and CI/CD jobs pull approved mitigations through the API or MCP, or diysca pushes them to a hand-off target (webhook, GitHub Actions, GitLab CI).
  3. The agent claims it, runs the playbook and reports running, done or failed. You can also set the status by hand on the mitigation's page.
  4. On done, diysca rescans the systems. Fixed findings move to Patched CVEs; the channels that alerted about them are told.

See docs/mitigations.md for the API calls, payloads and a GitHub Actions example.
